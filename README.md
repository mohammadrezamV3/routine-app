# Arion — نسخه Next.js

## نسخه: v1.87.0 (شروعِ زودهنگامِ درخواست‌های داده — کوتاه‌کردنِ زنجیرهٔ سریالِ لود)

### مسئله (اندازه‌گیری‌شده، نه حدسی)
لودِ لوکال هیچ‌وقت این رو نشون نمی‌داد چون تأخیرِ شبکه صفره. با تزریقِ تأخیرِ واقعی (۴۰۰ms در هر رفت‌وبرگشت، شبیهِ موبایلِ واقعی) روی `/weekly` معلوم شد:

```
 400ms  HTML می‌رسه
~800ms  باندلِ JS می‌رسه (رفت‌وبرگشتِ دوم)
~870ms  React هیدریت می‌کنه و *تازه* اولین درخواستِ داده می‌ره
~914ms  سنگین‌ترین‌ها (بازه‌های DailyEntry) تازه شروع می‌شن
~1200ms همه‌چیز رسیده
```

یعنی سه رفت‌وبرگشتِ **سریال** قبل از اولین بایتِ داده. خودِ درخواست‌ها سریع بودن — دیر **شروع** می‌شدن. روی `/exercise` بدتر بود: `/api/exercise/plan` در ۸۲۴ms و بعد `bodyMetrics` که منتظرش می‌موند، در ۱۰۴۲ms.

### چی تغییر کرد
- **`lib/preload.ts` + اسکریپتِ inline در `layout.tsx`** — درخواست‌های همیشگی همون لحظه‌ای که مرورگر HTML رو پارس می‌کنه فرستاده می‌شن، موازی با دانلودِ JS به‌جای بعدش. `lib/storage.ts` بعداً همون promiseها رو برمی‌داره، پس **هیچ درخواستِ اضافه‌ای ساخته نمی‌شه** — فقط زودتر شروع می‌شن.
- **بازهٔ DailyEntry هم پیش‌درخواست می‌شه** — عمداً یک بازهٔ *پهن* (۹۰ روز قبل تا ۷ روز بعد)، چون کشِ بازه‌آگاه هر زیربازه‌ای رو از یه بازهٔ پوشاننده می‌بره. این‌جوری لازم نیست حسابِ تاریخِ اسکریپت مو‌به‌مو با کامپوننت‌ها یکی باشه (که شکننده می‌بود). دو درخواستِ جدا شدن یکی.
- **پیش‌درخواستِ وابسته به مسیر** — `/exercise` هم `plan` هم `bodyMetrics` رو موازی می‌گیره (زنجیرهٔ سریال شکست)، `/trade` هم `checklist` و پنج کلیدِ تنظیماتش. `/api/trade/entries` عمداً بیرون موند: بازه‌اش ماهِ *جلالیِ* جاریه و تکرارِ اون حساب داخلِ اسکریپتِ inline شکننده می‌بود.
- **کوکیِ راهنمای `arion-auth`** — کوکیِ سشنِ next-auth از نوعِ httpOnlyه و JS نمی‌بیندش، پس بدونِ یه نشانهٔ جدا این اسکریپت برای مهمون‌ها هم چند تا ۴۰۱ الکی می‌فرستاد. **تصمیمِ امنیتی نمی‌گیره** — سرور همچنان خودش سشن رو چک می‌کنه؛ نبودنش فقط یعنی پیش‌درخواست انجام نمی‌شه. `SessionBridge` خودش با وضعیتِ واقعیِ سشن هم‌گام نگهش می‌داره (هم کاربرِ از قبل لاگین، هم سشنِ منقضی‌شده).
- **`SessionBridge`** — نتیجهٔ همون فچِ سشنی که `SessionProvider` می‌زنه رو به لایهٔ داده می‌رسونه، به‌جای `getSession()` که فچِ *مستقلِ دومی* می‌زد. `/api/auth/session` از ×۲ به ×۱ رسید.
- **اسکلتِ واقعی به‌جای `fallback={null}`** — `/exercise` و `/trade` هردو `<Suspense fallback={null}>` داشتن و چون محتواشون `useSearchParams()` صدا می‌زنه، Next همون `null` رو توی HTMLِ پری‌رندر می‌ذاشت: HTMLِ اولیهٔ این دو صفحه عملاً خالی بود (`/exercise` فقط ۴۳ کاراکتر متن). حالا `PanelSkeleton` — استاتیک، بدونِ JS — از همون اولین بایتِ HTML ساختارِ صفحه رو نشون می‌ده.
- **`dashboardPrefs` و `/api/account/avatar`** حالا از کش/پیش‌درخواستِ مشترک رد می‌شن (قبلاً `dashboardPrefs` فچِ خامِ خودش رو داشت، پس پیش‌درخواستش هدر می‌رفت و در تایم‌لاین دوبار دیده می‌شد).
- **`DashFriendsCard` برای مهمون دیگه درخواست نمی‌زنه** — دو تا ۴۰۱ در هر لودِ صفحه بود، در حالی که کارت همون حالتِ «وارد شوید» رو نشون می‌ده.

### نتیجه (RTT ۴۰۰ms، بیلدِ production، Postgres واقعی)
| صفحه | آخرین دادهٔ رسیده — قبل | بعد |
|---|---|---|
| `/exercise` | ۱۲۹۲ms | **۷۴۱–۷۸۴ms** |
| `/trade` | ۱۳۱۹ms | **۱۰۵۹–۱۱۲۸ms** |
| `/weekly` | ۱۲۱۰ms | **۸۶۴–۱۱۷۰ms** |

روی `/exercise` و `/weekly` همهٔ درخواست‌های بحرانی حالا در **یک موجِ موازی حدودِ ۵۱۰ms** می‌رن، به‌جای سه موجِ پشتِ‌سرهم.

> اعداد بینِ اجراها ~۲۰۰ms نوسان دارن؛ بازه‌ها همون نوسانِ واقعی‌ان، نه تخمین.

> چیزی که امتحان شد و **برداشته شد**: `SessionBridge` به‌تنهایی یه درخواست کم کرد ولی زمان رو عملاً تکان نداد — فرض اولیه‌ام که اون فچِ دوم *سریال* بود غلط بود، موازی بود. نگه داشته شد چون یه درخواستِ تکراری رو حذف می‌کنه و پلِ لازم برای هم‌گام‌سازیِ کوکیِ راهنماست، ولی سودِ زمانیش به‌ حسابِ این تغییر نوشته نشده.

## نسخه: v1.86.0 (کشِ بازه‌آگاه برای DailyEntry — حذفِ درخواست‌های هم‌پوشان)

### چی تغییر کرد
- **کشِ `lib/storage.ts` کلیدش URL بود، پس دو بازه‌ی تاریخیِ متفاوت هیچ‌وقت به‌هم نمی‌رسیدن — حتی اگه یکی کاملاً داخلِ اون یکی بود.** اندازه‌گیری روی `/weekly` نشون داد چهار درخواستِ هم‌پوشان از یک جدول می‌رفت: `range 08-13..08-27` (تایم‌لاینِ صفحه)، `range 05-22..08-19` (استریکِ ۹۰ روزه)، `range 08-15..08-21` (آمارِ همین هفته)، و `daily 08-20` (امروز — که *داخلِ* بازه‌ی اول بود).
- حالا بازه‌های درخواست‌شده نگه داشته می‌شن و اگه بازه‌ی تازه (یا یک روزِ تکی) زیرمجموعه‌ی یکی از اون‌ها باشه — چه رسیده باشه چه هنوز در راه — از همون بریده می‌شه، بدونِ درخواستِ جدید. **`/weekly`: ۱۵ → ۱۳ درخواست.**
- بازه‌ی ناموفق از کش بیرون انداخته می‌شه (تا یه قطعیِ لحظه‌ای بقیه رو گمراه نکنه) و اگه بازه‌ی پوشاننده شکست بخوره، خودِ درخواست‌کننده مستقیم می‌گیره، نه اینکه خالی برگردونه. نوشتن (`setDaily`) و ورود/خروج هم این کش رو پاک می‌کنن.

> چیزی که امتحان شد و **برداشته شد**: یه پنجره‌ی batchingِ هم‌تیکی که بازه‌های هم‌زمان رو در یک درخواستِ اجتماع‌شده بگیره. توی عمل هیچ سودی نداشت — دو بازه‌ی باقی‌مانده در دو موجِ جدا (با یک رفت‌وبرگشتِ شبکه فاصله) درخواست می‌شن، نه در یک تیک. ~۶۰ خط کدِ بی‌اثر بود، پس نگه داشته نشد.
## نسخه: v1.85.0 (سوییچِ فراخوانِ AI از Anthropic به گیت‌وی آروان‌کلود)

### چی تغییر کرد
- **همه‌ی چهار جای اپ که از AI استفاده می‌کنن** (تولید رودمپ، برنامه‌ی هوشمندِ ورزشی، جایگزینیِ حرکت، اسکنِ عکسِ غذا) دیگه مستقیم به Anthropic Messages API وصل نیستن — به گیت‌وی AIِ آروان‌کلود (GPT-4o-mini، با یک API سازگار با OpenAI روی endpointِ `chat/completions`) سوییچ کردن. `lib/anthropic.ts` به `lib/aiClient.ts` تغییرِ نام داد و همه‌ی ۴ فراخوان از یک تابعِ مشترک (`callAiChat`) رد می‌شن.
- **خروجیِ خام‌JSON دو لایه تضمین می‌شه**: هم با `response_format:{type:"json_object"}` در سطحِ خودِ فراخوان (پارامترِ استانداردِ OpenAI-compatible که مدل رو مجبور می‌کنه فقط JSON برگردونه)، هم با system promptِ صریح — دقیقاً همون الگویی که قبلاً برای Anthropic هم رعایت می‌شد.
- **آدرسِ گیت‌وی (شاملِ خودِ توکنِ دسترسی) هیچ‌جا کامیت نشده** — فقط از `process.env.ARVAN_AI_BASE_URL` خونده می‌شه؛ متغیرِ جدید توی `.env.example` (بدون مقدارِ واقعی) مستند شده، دقیقاً مثلِ `ANTHROPIC_API_KEY` قبلی.
- ⚠️ **این تغییر توی سندباکس تست‌شونده نیست**: شبکه‌ی این محیط به `arvancloudai.ir` دسترسی نداره (فقط چند دامنه‌ی محدود مثل registry.npmjs.org/anthropic.com اجازه دارن)، پس فراخوانِ واقعی به گیت‌وی از این‌جا قابل‌تأیید نبود. کد بر اساسِ قراردادِ استانداردِ OpenAI Chat Completions نوشته شده (که تقریباً همه‌ی گیت‌وی‌های `/v1` همینو پیاده می‌کنن)، ولی بعدِ دیپلوی حتماً یک تستِ واقعی (مثلاً ساختِ یک رودمپ) لازمه.

### برای دیپلوی
باید `ARVAN_AI_BASE_URL` رو با آدرسِ کاملِ گیت‌وی (همونی که شاملِ توکنه) به `.env` روی VPS اضافه کنی — دقیقاً مثلِ بقیه‌ی متغیرهای حساس، توی گیت کامیت نشه.

## نسخه: v1.84.0 (سخت‌سازیِ امنیتی ورودی‌ها + رفعِ N+1 و سبک‌سازیِ باندلِ ورزش)

### امنیت — هر مورد قبل از فیکس با حمله‌ی واقعی روی بیلدِ production تأیید شد

- **SQL Injection: ساختاراً ممکن نبود، و حالا نگهبان هم داره.** کلِ ریپو گشته شد: هیچ `$queryRaw`/`$executeRaw`/`*Unsafe`ای وجود نداره، هیچ‌جا ورودیِ کاربر با رشته داخلِ Prisma spread نمی‌شه (`where: {...body}`)، و همه‌ی کوئری‌ها شکلِ ثابت و پارامتری دارن — یعنی مقدارِ کاربر هیچ‌وقت به‌عنوان *ساختارِ* SQL تفسیر نمی‌شه. برای اینکه این تضمین با کدِ آینده نشکنه، `npm run check:sql` اضافه شد که APIهای خامِ Prisma رو می‌گیره و بیلد رو fail می‌کنه.
- **همه‌ی روت‌های تاریخ‌دار با ورودیِ بدشکل ۵۰۰ می‌دادن.** `?date=garbage`، `?date=9999-99-99`، `?date=2026-02-31` (سرریزِ تقویمی) همگی `new Date()` رو به `Invalid Date` می‌بردن، Prisma throw می‌کرد و روت با **HTTP 500ِ هندل‌نشده** می‌افتاد — هم راهِ ارزونِ اذیت‌کردنِ سرویس، هم ریختنِ استکِ خطا توی لاگ. `parseIsoDate()` اضافه شد (فقط `YYYY-MM-DD`ِ واقعی، با گرفتنِ سرریزِ تقویمی) و همه‌ی این روت‌ها حالا ۴۰۰ می‌دن.
- **بازه‌های تاریخیِ بی‌انتها.** `from=0001-01-01&to=9999-12-31` با ۲۰۰ جواب می‌گرفت و عملاً یه full-table scan بود. حالا `parseDateRange()` سقفِ ۴۰۰ روز می‌ذاره و روت‌های پرحجم `take` هم گرفتن.
- **`/api/settings/[key]` یه فروشگاهِ کلید/مقدارِ نامحدود بود.** یک کاربرِ لاگین‌کرده می‌تونست (۱) بی‌نهایت کلیدِ دلخواه بسازه و **۳ مگابایت** توی هرکدوم بریزه — تست شد، قبول و ذخیره و کامل هم پس داده شد؛ و (۲) `pushSentLog` رو بازنویسی کنه، همون کلیدی که کرانِ سرور می‌خونه تا بفهمه یادآوریِ امروز فرستاده شده — با تاریخِ آینده، یادآوری‌ها برای همیشه خفه می‌شدن. حالا allowlistِ کلیدها (`lib/userSettingKeys.ts`)، جداسازیِ کلیدهای «مدیریت‌شده توسط سرور»، و سقفِ ۶۴KB روی هر مقدار.
- **هیچ سقفی روی بدنه‌ی درخواست نبود.** Next برای route handlerها پیش‌فرضی نمی‌ذاره. `readJsonBody()` اضافه شد (سقفِ ۲۵۶KB، سنجشِ بایتِ واقعی نه طولِ رشته، چون متنِ فارسی چندبایتیه) و روت‌های نویسنده بهش وصل شدن.
- **`/api/market/prices` کاملاً باز بود.** بدونِ هیچ حسابی ۲۰۰ می‌داد — یعنی هرکسی می‌تونست از این سرور به‌عنوان پروکسیِ رایگانِ یاهو استفاده کنه (هزینه‌ی پهنای‌باند + ریسکِ بلاک‌شدنِ IPِ سرور). بدتر: کشِ داخلیش هیچ سقف/تخلیه‌ای نداشت، پس با نمادهای ساختگیِ بی‌نهایت می‌شد بی‌سروصدا حافظه‌ی پروسه رو پر کرد. حالا لاگین لازمه، سقفِ نرخ داره، نماد با regex اعتبارسنجی می‌شه، و کش سقفِ ۲۰۰ ورودی با تخلیه‌ی LRU-ish داره.
- **ورودی‌های جستجو بی‌سقف بودن** (`notepad/search`، `friends/search`، `calorie/foods`) — یه `q`ی چندصدکیلوبایتی روی هر ردیف/بلاک اجرا می‌شد. همه با `clampQuery()` بریده شدن.
- **رمزِ کرانِ `/api/push/send-reminders` با `!==` مقایسه می‌شد** (نشتِ زمانی). حالا `timingSafeEqual`، با رسیدگی به طولِ نابرابر.
- **سقف روی ستون‌های `Json`**: `completedItems` (روتین و ورزش) هر چیزی که فرستاده می‌شد رو عیناً ذخیره می‌کرد؛ حالا فقط کلیدهای معتبر، با سقفِ تعداد و طول.

### بهینه‌سازی

- **N+1 در `/api/friends`** — برای *هر* دوست ۵ کوئری جدا می‌زد (تنظیمات + رکوردِ امروز + ۹۰ روز تاریخچه + ساعتِ بیداری). با pg_stat_statements اندازه گرفته شد: **۲۶ کوئری برای ۲۰ دوست → ۵ کوئری**، و مهم‌تر اینکه دیگه با تعدادِ دوست رشد نمی‌کنه (۱۰۰ دوست هم همون ۵ تا). زمانِ پاسخ روی لوکال ۶۵ms → ۲۷ms.
- **N+1 در کرانِ یادآوری‌ها** — به‌ازای هر کاربرِ سابسکرایب‌شده ۴ تا ۶ کوئریِ جدا برای تنظیمات، و یک نوشتنِ دیتابیس به‌ازای *هر یادآوری*. حالا یک کوئریِ دسته‌ای برای خواندن و یک نوشتن به‌ازای هر کاربر.
- **۸۵KB کاتالوگِ حرکات از باندلِ صفحه‌ی `/exercise` بیرون رفت.** ریشه‌ش یه لبه‌ی نامرئی بود: چند کامپوننتِ کلاینتی فقط برای *typeِ* `ExerciseDay` ماژولِ `exercisePlans` رو import می‌کردن، و اون ماژول `EXERCISE_CATALOG` رو static import می‌کرد — پس کلِ اون دیتا توی باندلِ صفحه می‌نشست، حتی برای کسی که هیچ‌وقت لیستِ حرکات رو باز نمی‌کنه. توابعِ وابسته به کاتالوگ به `lib/exerciseCatalogUtils.ts` منتقل شدن، importهای صرفاً typeای به `import type` تبدیل شدن، و دو مودالِ سنگین `dynamic()` شدن. نتیجه: **`/exercise` از ۴۹.۴kB/۲۳۵kB به ۳۳.۵kB/۲۱۶kB**؛ کاتالوگ حالا یه chunkِ جداست که فقط با کلیک لود می‌شه.

### نگهبان‌های جدید (`npm run check`)
- `check:sql` — هر SQLِ خامی که به کد اضافه بشه رو می‌گیره.
- `check:settings` — هر کلیدِ تنظیماتی که استفاده بشه ولی توی allowlist نباشه رو می‌گیره. (لازم بود: همین بررسی شش کلیدِ trade/bodyMetrics رو گرفت که اولین نسخه‌ی allowlist جا انداخته بود و در production بی‌سروصدا با ۴۰۰ می‌شکستن.)

### چطور تست شد
بیلدِ production + Postgres واقعی + کاربرِ تست + ۲۰ دوستِ seed‌شده:
- **۱۸ تستِ حمله/رگرسیون، همه سبز** — تاریخِ بدشکل ۴۰۰، بازه‌ی بی‌انتها ۴۰۰، کلیدِ دلخواه ۴۰۰، `pushSentLog` ۴۰۰، بدنه‌ی ۳MB ۴۱۳، market بدونِ لاگین ۴۰۱، کرانِ بدون/غلط ۴۰۱ و با رمزِ درست ۲۰۰، و همه‌ی مسیرهای سالم همچنان ۲۰۰.

- بدنسازی — مرورِ برنامه: دکمه‌ی «ویرایش» از پایینِ صفحه حذف شد؛ به‌جاش هر باکسِ روز یه آیکونِ مدادِ گوشه‌ی بالا-چپِ خودش داره که مستقیم می‌بره تو نمای همون روز برای ویرایش. متنِ دکمه‌ی نهایی هم از «ثبتِ برنامه» (با اعرابِ زیرِ ث که بد رندر می‌شد) به «ثبت برنامه» ساده تغییر کرد.
- بدنسازی — دیاگرامِ عضلاتِ درگیر: هر عضله حالا یه خطِ دورِ نازک داره که از عضله‌های کناری جداش می‌کنه (دقیقاً مثلِ عکسِ آناتومیِ مرجع)، و عضله‌های غیرفعال هم شفافیتِ بیشتری گرفتن تا همیشه قابلِ‌تشخیص باشن، نه فقط عضله‌ی هدف.

### چی تغییر کرد
- بدنسازی — افزودنِ دستی: موقعِ تعیینِ مشخصاتِ یک حرکت دیگه ازت نمی‌پرسه «ست‌وتکراره یا زمانی» — از روی الگوی خودِ حرکت (کاردیو/انعطاف‌پذیری = زمانی، بقیه = ست‌وتکرار) خودکار تشخیص می‌ده و فقط فیلدهای مربوطه رو نشون می‌ده.
- بدنسازی — مشاهده حرکات: بک‌گراندِ پاپ‌آپ و کارتِ جزئیات بلورِ بیشتر/کدرتری گرفتن (بلور ۲۲→۳۲px، شفافیتِ کمتر) چون قبلی خیلی شفاف بود و پشتش زیادی معلوم بود.

### چی تغییر کرد
- بدنسازی — کارتِ جزئیاتِ حرکت: دیگه چسبیده به لبه‌ی پایینِ صفحه نیست — مثلِ پاپ‌آپِ اصلی یه کارتِ شناورِ گردِ کامله؛ اسمِ حرکت از کنارِ ضربدر رفت زیرِ جای‌عکس؛ فاصله‌ی بخش‌ها فشرده‌تر و منظم‌تر شد.
- بدنسازی — دیاگرامِ عضلاتِ درگیر: کاملاً بازسازی شد با یه سیلوئتِ توپرِ بدن (نه فقط طرح‌واره‌ی خط‌دور) به‌عنوانِ زمینه، پشتِ منحنی‌های هر عضله.
- بدنسازی — افزودنِ دستی: بک‌گراندِ پاپ‌آپِ «افزودن حرکت» دوباره برگشت به سبکِ شیشه‌ایِ هدر (نه سیاه)؛ دکمه‌ی «مرحله بعد» کوچیک‌تر شد؛ فونتِ تایتلِ «کدوم روزها...» بزرگ‌تر شد؛ ردیف‌های حرکتِ ثبت‌شده‌ی هر روز دقیقاً هم‌سبکِ ردیف‌های «مشاهده حرکات» شدن.

### چی تغییر کرد
- بدنسازی — افزودنِ دستی: باکسِ «روز ...» بزرگ‌تر و پررنگ‌تر شد (پدینگ/فونت/رادیوسِ بیشتر) چون تنها لنگرِ بصریِ صفحه بود؛ بک‌گراندِ پاپ‌آپِ «افزودن حرکت» حالا مشخصاً سیاهه (هم‌سبکِ بلورِ هدر، نه شیشه‌ای‌ِ کم‌رنگِ مشترکِ مشاهده‌ی حرکات).
- بدنسازی — مشاهده حرکات: ۸ حرکتِ رایجِ جامانده اضافه شد (۱۴۱ به ۱۴۹): پرس سینه دست جمع، پرس سینه دکلاین، اسکوات تک‌پا، پروانه معکوس دمبل، پروانه معکوس دستگاه، دراز و نشست، بالا آوردن پا خوابیده، کرانچ معکوس.
- بدنسازی — کارتِ جزئیاتِ حرکت: دکمه‌ی ضربدر که به‌خاطرِ نبودِ کلاسِ dash-scope روی این کارتِ پورتال‌شده بک‌گراندِ پیش‌فرضِ سراسریِ دکمه‌ها رو گرفته بود، حالا شفافه؛ دستگیره‌ی اسلایدِ بالای کارت حذف شد؛ تایتل‌های داخلی (میزانِ سختی/دستورالعمل/عضلاتِ درگیر/مزایا) رنگِ اکسنت گرفتن.
- بدنسازی — دیاگرامِ عضلاتِ درگیر: به‌جای rect/circle/ellipseِ خامِ قبلی، حالا هر عضله یک مسیرِ بزیه‌ایِ دست‌ساز داره که شکلِ واقعی‌ترِ سینه/شکمِ سیکس‌پک/جلوبازوی دوکی/باسنِ گرد/... رو دنبال می‌کنه، و طرح‌واره‌ی بدن هم با سر/گردن/تنه/دست/پای منحنی‌تر جایگزین شد.

### چی تغییر کرد
- بدنسازی — مشاهده حرکات: گوشه‌های پاپ‌آپ گردتر شدن (سبکِ اپل)؛ ردیفِ هر حرکت دیگه توضیحِ گروهِ عضلانی نداره — فقط اسمِ حرکت و میزانِ سختی (ستاره) سمتِ چپ.
- بدنسازی — افزودنِ دستی: کلیک روی هر روز (مثلاً شنبه) دیگه نیاز به یه لیستِ جداگانه‌ی زیرِ پیل‌ها نداره — مستقیم می‌ره توی باکسِ همون روز؛ عنوانِ «حرکات این روز» شد «روز شنبه» و تایتلِ تکراریِ بالای صفحه حذف شد. توی پاپ‌آپِ «افزودن حرکت»: جهتِ نوارِ جستجو (که با dir="auto" قاطی می‌شد) با dir="rtl" فیکس شد و بک‌گراندش هم‌سبکِ هدرِ سایت شد؛ ردیف‌های حرکت دقیقاً هم‌سبکِ «مشاهده حرکات» (اسم + ستاره‌ی سختی، بدون توضیح) شدن؛ دکمه‌ی «افزودن» (که چون پاپ‌آپ پورتال‌شده به body بود، به‌جای استایلِ پیلِ سبز می‌افتاد رو دایره‌ی نقطه‌چینِ پایه) با کلاسِ مستقلِ خودش درست شد و آیکونِ «+» کنارش حذف شد.

### چی تغییر کرد
- بدنسازی — افزودن با AI: تایتلِ «قد و وزن خود را وارد کنید» با فونتِ بزرگ‌تر نوشته می‌شه؛ اینتر توی فیلدِ قد کاربر رو می‌بره فیلدِ وزن، و اینتر توی فیلدِ وزن (وقتی هر دو فیلد پر باشن) خودکار می‌ره مرحله‌ی بعد.
- بدنسازی — افزودنِ دستی: کلیک روی هر روز مستقیم واردِ باکسِ همون روز می‌شه؛ دکمه‌ی «افزودن» به‌جای رندرِ اینلاینِ لیستِ کاتالوگ، یه پاپ‌آپِ مستقل باز می‌کنه (دقیقاً مثلِ پاپ‌آپِ «مشاهده حرکات»)؛ کارتِ تعیینِ مشخصاتِ حرکت فقط یک ضربدرِ بی‌بک‌گراند بالا داره که برمی‌گردونه به لیستِ جستجو؛ دکمه‌های افزودن/بازگشت/بستن/ثبتِ باکسِ روز همه بی‌بک‌گراند شدن؛ بعدِ تکمیلِ همه‌ی روزها یه مرحله‌ی «مرورِ برنامه» جدید کلِ برنامه رو نشون می‌ده با دکمه‌ی ثبتِ نهایی و دکمه‌ی «ویرایش» که برمی‌گردونه به لیستِ روزها.

### چی تغییر کرد
- بدنسازی — کاتالوگِ حرکات: پاپ‌آپِ «مشاهده حرکات» وسطِ صفحه نمی‌نشست (باگِ تداخلِ ترنسفورمِ framer-motion با سنترینگِ CSS‌ی کلاسِ پایه) — حالا با یه wrapperِ فلکس‌باکسِ مستقل کاملاً وسط می‌شینه؛ بک‌گراند/بلورِ کارتِ جزئیات هم با استایلِ شیشه‌ایِ جدیدِ خودِ پاپ‌آپ هماهنگ شد.
- بدنسازی — افزودن با AI: آیکونِ اخطارِ کنارِ پیامِ خطای هر فیلد جلوی متن می‌افتاد نه پشتش — ترتیبش برعکس شد؛ تایتلِ اصلیِ صفحه‌ی انتخابِ «افزودن برنامه» بزرگ‌تر شد و فاصله‌ی بیشتری از بالا و از ردیفِ انتخابِ زیرش گرفت؛ دکمه‌ی «مرحله بعد» کوچیک‌تر و پرِ توپر (بک‌گراندِ رنگیِ اکسنت به‌جای فقط بوردر) شد.

## نسخه: v1.40.0 (پولیشِ فرمِ افزودنِ برنامه، کاتالوگِ حرکات به‌شکلِ پاپ‌آپ + ستاره‌ی سختی)

### چی تغییر کرد
- بدنسازی — افزودن با AI: دکمه‌ی «مرحله بعد» چپ‌چین شد (نه تمام‌عرض)، نقاطِ پیشرفتِ مراحل رفتن پایینِ صفحه (کنارِ همون دکمه)، خطای هر فیلد (قد/وزن) حالا با آیکونِ اخطار کنارش نشون داده می‌شه، و تایتلِ اصلیِ هر مرحله (مثلاً «قد و وزن خود را وارد کنید») با فونتِ بزرگ‌تر از لیبل‌های زیرفیلد نوشته می‌شه.
- بدنسازی — افزودنِ دستی: دکمه‌ی «افزودن» توی باکسِ «حرکات این روز» حالا متن+آیکون داره و سبزه؛ خودِ باکس بزرگ‌تر شد؛ عنوانِ «کدوم روزها رو می‌خوای برنامه داشته باشی؟» تصحیح و فاصله‌اش بیشتر شد؛ دکمه‌ی «ثبتِ برنامه» پرِ توپر و کاملاً گرد شد (نه فقط بوردر).
- بدنسازی — مشاهده حرکات: به‌جای صفحه‌ی تمام‌عرض، حالا یک پاپ‌آپ استاندارده (هم‌بک‌گراند/بلورِ هدرِ سایت)؛ فیلدِ جستجو راست‌چینِ اجباری شد؛ میزانِ سختیِ هر حرکت با ستاره (تا ۵ ستاره، بر اساسِ الگوی حرکتی) توی کارتِ جزئیات نشون داده می‌شه.

## نسخه: v1.38.0 (ریدیزاینِ کاملِ افزودنِ برنامه — AI و دستی)

### چی تغییر کرد
- بدنسازی — افزودن با AI: خطای قد/وزن حالا زیرِ همون فیلد نشون داده می‌شه؛ ترتیبِ مراحل به قد/وزن → هدف → روزها+سطح → توضیح تغییر کرد (حداقلِ روزهای هر هدف الان درست و با توجه به سطحِ واقعی چک می‌شه)؛ هدرِ فرم فقط یک دکمه‌ی آیکونیِ بازگشت + بستن داره (بدونِ تایتلِ ثابت)؛ متنِ مرحله‌ی اول و دوم واضح‌تر شد؛ باکسِ توضیحات مستطیلی و راست‌چین شد و دیگه ریسایز نمی‌شه؛ فاصله‌های همه‌ی مراحل بیشتر شد.
- بدنسازی — افزودنِ دستی: کلاً ریدیزاین شد — اول روزهای هفته رو (چندتایی) انتخاب می‌کنی، بعد با کلیک روی هر روز وارد نمای اختصاصیِ همون روز می‌شی و از اونجا حرکت اضافه می‌کنی؛ «تمرکزِ امروز» رو دیگه خودت تایپ نمی‌کنی — سیستم از روی حرکاتِ اضافه‌شده تشخیص می‌ده؛ دیگه نیازی به قبول‌کردنِ قوانین نیست.
- مشاهده حرکات: کاتالوگ حدود ۴۵ حرکتِ جدید (دستگاه/سیم‌کش/کاردیو/انعطاف‌پذیری) گرفت؛ جستجو+فیلتر+لیست همه توی یک باکسِ واحد شدن؛ ردیف‌های لیست دیگه جای‌عکس ندارن؛ اسکرول‌بارها مخفی شدن؛ دکمه‌ی بازگشت فقط آیکونه.

- آیکونِ هوش‌مصنوعی از آیکونِ ربات به یه ستاره‌ی ۴پر طلاییِ درخشان (سبکِ جمینای) با انیمیشنِ چرخش/پالسِ بی‌نهایت تغییر کرد (`AiSparkleIcon`).
- باگِ چشمک‌زدنِ صفحه‌ی onboarding سرِ هر ریلودِ صفحه‌ی بدنسازی: چون وضعیتِ `loading`ِ اولیه‌ی سشن مثلِ `unauthenticated` رفتار می‌کرد، هر بار قبل از این‌که سشنِ واقعی چک بشه یه لحظه فرمِ «بدونِ برنامه» به‌جای داشبورد نشون داده می‌شد.
- اندازه‌ی حلقه‌های درصدِ کارتِ آمارِ بدنسازی به همون اندازه‌ی حلقه‌های داشبوردِ روتین (۷۲پیکسل) برگشت تا کارت‌ها هم‌قد بشن.
- «برنامه تمرینی امروز» به «برنامه تمرینی» کوتاه شد؛ دکمه‌ی «افزودن برنامه» کنارِ همین تیتر جابه‌جا شد (هم‌الگوی دکمه‌ی «افزودن» توی روتین).
- آیکونِ زنگوله‌ی «یادآوری‌ها»: وقتی اطلاعیه‌اش فعاله زنگوله پره، وقتی غیرفعاله زنگوله توخالیه؛ روز و ساعتِ هر یادآوری هم حالا توی یک خط کنارِ هم نشون داده می‌شن.
- استریک هیچ‌وقت کار نمی‌کرد چون ثبتِ ساعتِ بیداری فقط از داخلِ `DayModal` ممکن بود، ولی `DayModal` این‌روزها فقط با انتخابِ تاریخ صدا زده می‌شه، نه برای ثبتِ بیداریِ امروز — یعنی هیچ‌کس هیچ‌وقت نمی‌تونست بیداریش رو ثبت کنه و استریک همیشه صفر می‌موند. یه دکمه‌ی «ثبت بیداری الان» مستقیماً توی صفحه‌ی «روتین من» اضافه شد.
- توی حالتِ روز (light mode)، کارت‌های داشبورد (`bg-dash-card`) از بک‌گراند تقریباً جدا نبودن چون اورلیِ سفیدشون فقط ۲٪ بود (مقداری که برای حالتِ تاریک درسته)؛ الان توی حالتِ روز این اورلی ۵۵٪ می‌شه، هم‌الگوی بقیه‌ی کارت‌های اپ.

## نسخه: v1.28.1 (فیکسِ عرضِ داشبوردِ بدنسازی + چیدمانِ سه‌بخشی + دکمه‌های بی‌بک‌گراند)

### چی تغییر کرد
- ریشه‌ی چندتا باگِ داشبوردِ بدنسازی پیدا شد: خودِ کانتینرِ صفحه (`.bodybuilding-glass`) یه عرضِ ثابتِ ۹۰۰پیکسلی از نسخه‌ی قدیمیِ فرم‌محور داشت، درحالی‌که داشبوردِ روتین با `.dash-breakout` تا ~۱۳۲۰پیکسل باز می‌شه — همین باعث می‌شد نوارِ روزها کمتر از روتین جا بگیره. الان فقط تبِ «بدنسازی» (نه کالری) عیناً هم‌عرضِ داشبوردِ روتینه.
- داشبوردِ بدنسازی داخلِ `.dash-scope` نبود (داشبوردِ روتین هست) — همین یعنی دکمه‌های Tailwindِ داشبورد (شروع/پایان تمرین، افزودنِ برنامه، ...) به‌جای بک‌گراندِ شفافِ داشبورد، بک‌گراندِ لیکوئیدگلسِ پیش‌فرضِ کلِ سایت رو می‌گرفتن. اضافه‌شدنِ `dash-scope` این‌و حل کرد؛ چندجای دیگه هم که خودم دستی بک‌گراند ست کرده بودم (دکمه‌ی شروع/پایان تمرین، دکمه‌های انتخابِ AI/دستی) به همون سبکِ بوردر-فقط بقیه‌ی دکمه‌های اصلیِ اپ برگشت.
- چیدمان به همون سه‌بخشیِ داشبوردِ روتین برگشت: راست «برنامه تمرینی امروز» (با دکمه‌ی «افزودن برنامه ورزشی جدید» همون ردیفِ تیتر)، وسط یک دکمه‌ی تکِ «مشاهده حرکات» (بدونِ پیش‌نمایشِ لیست)، چپ آمار+دوستان زیرِ هم.
- تبِ «بدنسازی/کالری» بالای صفحه کوچیک و راست‌چین شد؛ خطِ «سطح: ...» بالای داشبورد حذف شد.
- «شروع دوباره» بعدِ پایانِ تمرین حذف شد.
- اگه تعدادِ حرکاتِ امروز از جای باکس بیشتر بشه، خودِ لیست اسکرول می‌شه (اسکرول‌بارِ نازک بدونِ بک‌گراند، هم‌رنگِ تم) و باکس کش نمیاد؛ دکمه‌ی شروع/پایانِ تمرین همیشه چسبیده به تهِ باکس می‌مونه.

### چی تغییر کرد
- بخشِ «بدنسازی» کاملاً بازطراحی شد تا دقیقاً هم‌ساختار داشبوردِ «روتین من» باشه: همون نوارِ روزها (امروز/تاریخچه)، همون کارتِ «دوستان» (نسخه‌ی مخصوصِ بدنسازی، فقط پیشرفتِ همین ماژول رو نشون می‌ده)، و همون الگوی کارت‌ها/دکمه‌ها.
- کارتِ جدیدِ «تعداد جلسات» بالای صفحه: چند جلسه از این هفته رفتی/مونده، به‌همراه دو حلقه‌ی درصدِ پیشرفتِ امروز و هفتگی.
- کارتِ «وضعیتِ امروز»: استریکِ روزهای متوالیِ تمرین (فقط روزهای واقعیِ باشگاهِ برنامه حساب می‌شه) + پیغامِ «امروز هنوز تمرین نکردی» وقتی امروز روزِ باشگاهه و هنوز چیزی ثبت نشده.
- «برنامه تمرینی امروز»: با دکمه‌ی «شروع تمرین» یک تایمر می‌افته، حرکت‌ها رو می‌تونی حین تمرین تیک بزنی، و با «پایان تمرین» جلسه ثبت می‌شه — هر حرکتی که تیک نخورده باشه یک ضربدرِ قرمز می‌گیره (دقیقاً منطقِ «برنامه‌ی گذشته‌ی تیک‌نخورده»ی روتین).
- «مشاهده حرکات»: کاتالوگِ کاملِ حرکاتِ بدنسازی با جستجو؛ کلیک روی هرکدوم نحوه‌ی انجام، عضلاتِ درگیر و مزایاش رو نشون می‌ده.
- «افزودن برنامه ورزشی جدید» حالا دو مسیر داره: ساختِ خودکار با هوش‌مصنوعی (فرمِ قبلی) یا واردکردنِ دستیِ برنامه‌ی شخصیِ خودِ کاربر (روز‌به‌روز، بدونِ پرسش‌نامه‌ی سطح/هدف).
- دکمه‌ی چرخشیِ کنارِ هر حرکت («این تجهیزات رو ندارم») حالا آیکونه، نه دکمه‌ی متنی — با همون منطقِ جایگزینیِ قبلی.
- «برنامه هفتگی» پایینِ صفحه هم به همون آکاردئونِ باز/بسته‌شونده‌ی روتین (week-day) تبدیل شد.
- زیرساخت: `ExerciseLog` حالا حرکاتِ تیک‌خورده‌ی هر جلسه رو هم ذخیره می‌کنه (`completedItems`)، و `/api/friends` می‌تونه پیشرفتِ بدنسازیِ دوستان رو هم برگردونه (`?module=exercise`).

### چی تغییر کرد
- بک‌گراندِ پاپ‌آپ‌های افزودن/ویرایش/انتقالِ برنامه، و پنل‌های پروفایل/اطلاعیه‌های هدر، الان دقیقاً هم‌رنگِ خودِ هدر (شیشه‌ای/نیمه‌شفاف) هستن — قبلاً یه گرادیانِ تیره‌ی جدا داشتن.
- دکمه‌ی «میزان اهمیت» توی پاپ‌آپِ فیلتر کار نمی‌کرد؛ الان با انتخابِ هر سطح، لیستِ چک‌باکسِ برنامه‌ها فقط برنامه‌هایی که همون سطحِ اهمیت رو دارن نشون می‌ده، و یه دکمه‌ی تیک برای اعمالِ نهایی اضافه شد.
- از روزهای گذشته دیگه نمی‌شه برنامه حذف کرد (مثلِ منطقِ «انتقال» که قبلاً بلاک شده بود) — هم توی منوی سه‌نقطه‌ی «برنامه‌های امروز» هم توی تابعِ حذفِ خودِ صفحه.
- باگِ سه‌نقطه‌ی «برنامه‌های امروز» فیکس شد: هاور روی هر ردیف باعث می‌شد ردیفِ پایینی بپره بالا (به‌خاطرِ یه انیمیشنِ `y: -2` روی هاور که لازم نبود).
- توی پاپ‌آپِ افزودن/ویرایشِ برنامه، دکمه‌ی دایره‌ایِ «−» برای حذفِ ردیف با یه دکمه‌ی متنیِ قرمزِ «حذف این روز» جایگزین شد، با جایگذاریِ درست‌تر (زیرِ فیلدهای ساعت).
- وقتی هرکدوم از پاپ‌آپ‌های هدر (پروفایل/اطلاعیه‌ها) باز بود، کلیک روی بقیه‌ی صفحه نمی‌بستشون — الان با کلیک روی هرجای صفحه بسته می‌شن (همون راه‌حلی که برای منوی سه‌نقطه قبلاً جواب داده بود).
- برنامه‌ای که ساعتش گذشته و تیک نخورده، الان به‌جای دایره‌ی خالی یه ضربدرِ قرمز با پس‌زمینه‌ی قرمز و انیمیشنِ پالس نشون می‌ده.
- ستونِ درصدِ سمتِ چپِ نمودارِ «آمار هفتگی» (۱۰۰٪/۵۰٪/۰٪) حذف شد.

### چی تغییر کرد
- منوی سه‌نقطه‌ی «برنامه‌های امروز» بک‌گراندش تقریباً شفاف بود (فقط ۲٪ سفید + backdrop-blur) — الان مثلِ بقیه‌ی منوهای شناورِ اپ یه بک‌گراندِ تقریباً توپر داره، همیشه خواناست.
- کارتِ «یادآوری‌ها»: هر آیتم الان سه خط جداست (اسم / روز / ساعتِ شروع‌وپایان)، بدون خطِ تیره بینِ روز و ساعت، و همه‌ی باکس‌ها حداقل‌ارتفاعِ یکسان دارن.
- توی «برنامه هفتگی»، آیتم‌هایی که ساعتشون خیلی نزدیکِ بیداری/خواب بود روی لیبلِ همون نقطه‌ی انتهایی overlap می‌کردن — فاصله‌ی امنِ لبه‌ها (EDGE_GAP) بیشتر شد.
- فیلترِ جست‌وجوی برنامه/تگ الان قبل از مقایسه، «ي»/«ك» عربی رو به «ی»/«ک» فارسی و نیم‌فاصله رو به فاصله نرمالایز می‌کنه (`normalizeFa` توی `lib/utils.ts`) — قبلاً اگه اسمِ برنامه با کیبوردِ عربی تایپ شده بود، جست‌وجو با کیبوردِ فارسی چیزی پیدا نمی‌کرد.
- تقویمِ انتخابِ تاریخ (`JalaliDatePicker`، همه‌جا از افزودنِ برنامه تا انتقال) دیگه از `<select>` بومیِ مرورگر برای ماه/سال استفاده نمی‌کنه — یه دراپ‌داونِ کاملاً سفارشی و هم‌رنگِ اپ جایگزینش شد که لیستِ ۱۰۰+ سالِ داخلش هم اسکرول‌بارِ خامِ مرورگر نداره.
- توی پاپ‌آپِ افزودنِ برنامه، بعضی تایتل‌ها (`<label>`های اصلی) به‌خاطرِ یه تای اسپسیفیسیتیِ CSS خاکستری می‌موندن درحالی‌که بقیه (تاریخ‌ها/ساعت‌ها) سبز بودن — الان همه یک‌دست سبزن. فاصله‌ی زیادِ بینِ لیبلِ «میزان اهمیت» و باکسِ زیرش هم اصلاح شد.
- هدر: کلیک روی پروفایل/زنگوله‌ی اعلان‌ها/همبرگر همزمان چندتاشون رو باز نگه می‌داشت — الان باز کردنِ هرکدوم اون دوتای دیگه رو می‌بنده. پنلِ پروفایل هم چون خیلی نزدیکِ لبه‌ی راستِ صفحه بود و وسط‌چین می‌شد، گاهی نیمه‌ش از صفحه می‌زد بیرون — حالا از لبه‌ی راستِ دکمه‌ی خودش باز می‌شه به‌جای وسط‌چین‌شدن، همیشه داخلِ صفحه می‌مونه.

## نسخه: v1.25.6 (اصلاحِ منطقِ انتقال + دکمه‌ی حذفِ ردیف + یادآوری‌های نزدیک)

### چی تغییر کرد
- کارتِ «یادآوری‌ها» الان فقط برنامه‌های «امروز» و «فردا» رو نشون می‌ده (قبلاً کلِ هفته بود) — واقعاً یادآوریِ چیزیه که نزدیکه، نه هرچی توی هفته با تگِ اهمیتِ بالا ثبت شده. اگه تعداد زیاد بشه، کارت خودش اسکرول می‌شه (بدون اسکرول‌بارِ قابل‌دیدن)، دیگه تا ته صفحه کش نمیاد.
- باگِ دکمه‌ی «−» توی افزودن/ویرایشِ برنامه فیکس شد: قبلاً وقتی دو ردیف بود، دکمه‌ی حذفِ ردیفِ اول دقیقاً روی مرزِ بینِ دو ردیف می‌نشست و معلوم نبود مالِ کدومه («حسِ دوتا دکمه‌ی منفی»)؛ الان کنارِ خودِ day-picker همون ردیفه، همیشه واضحه کدوم ردیف رو حذف می‌کنه.
- «روز مقصد» توی پاپ‌آپِ انتقال شد «انتقال به روز:».
- باگِ تقویمِ انتقال فیکس شد: قبلاً اگه مثلاً برنامه دوشنبه بود، همه‌ی شنبه/یکشنبه‌های تقویم (حتی هفته‌های آینده) غیرفعال می‌شدن؛ الان فقط تاریخ‌هایی که واقعاً از امروز گذشتن غیرفعالن — چون برنامه‌ها هفتگی تکرار می‌شن، شنبه/یکشنبه‌ی هفته‌ی بعد کاملاً معتبره.
- دکمه‌ی ثبتِ پاپ‌آپِ انتقال هم مثلِ افزودن/ویرایش، چپ‌چین شد.
- تیکِ «ساعتش هم تغییر کنه» حذف شد — فیلدهای ساعتِ شروع/پایان همیشه توی پاپ‌آپِ انتقال هستن، پیش‌فرض همون ساعتِ فعلیِ برنامه، کاربر آزاد که تغییرشون بده یا نه.
- بک‌گراندِ پشتِ پاپ‌آپ‌های افزودن/ویرایش/انتقالِ برنامه بلورِ بیشتر و تیره‌تر گرفت (حسِ مات‌تر).

## نسخه: v1.25.5 (پرداختِ ریزه‌کاری‌هایِ پاپ‌آپِ افزودن/انتقالِ برنامه)

### چی تغییر کرد
- پاپ‌آپِ «انتقال به یک روز دیگر»: دیگه نمی‌شه به روزی زودتر از روزِ فعلیِ خودِ برنامه منتقل کرد (مثلاً از دوشنبه به یکشنبه یا شنبه) — چون برنامه‌ها هفتگی تکرار می‌شن، «زودتر» یعنی موقعیتِ روز توی ترتیبِ هفته (شنبه..جمعه)، نه فقط گذشته‌بودنِ تاریخِ تقویمی. روزهای غیرمجاز توی خودِ تقویم خاکستری/غیرفعالن، هم موقعِ ثبت دوباره چک می‌شه.
- ساعتِ برنامه‌ها توی کارتِ «یادآوری‌ها» با عددِ انگلیسی نمایش داده می‌شه (قبلاً فارسی بود، هماهنگ نبود با بقیه‌ی جاهای اپ).
- دکمه‌ی ثبت (تیک) توی پاپ‌آپِ افزودن/ویرایشِ برنامه از دکمه‌ی «افزودن روز دیگر» جدا شد — «افزودن روز دیگر» سمتِ راست می‌مونه، دکمه‌ی ثبت با یه فاصله (`space-between`) میره سمتِ چپِ همون ردیف.
- خودِ باکسِ پاپ‌آپ کمی بزرگ‌تر شد (تا معمولاً همه‌چیز بدونِ اسکرول جا بشه) و اسکرول‌بارش کامل مخفی شد (لمس/درگ همچنان اسکرول می‌کنه، برای حالتِ چندتا ردیفِ روز).

- **ورود**: حداکثر ۸ تلاش ناموفق در ۱۰ دقیقه، هم به‌ازای IP هم به‌ازای همون
  شناسه ورود (یوزرنیم/موبایل/ایمیل) — جلوگیری از brute-force روی رمز عبور
- **ساخت رودمپ با AI**: حداکثر ۱۰ در ساعت به‌ازای هر کاربر (چون هر بار
  یعنی هزینه واقعی روی Claude API)

⚠️ محدودیت مهم این پیاده‌سازی: فقط در سطح یک instance کار می‌کنه. اگه
بعداً اپ روی چند سرور/serverless پخش بشه، باید با یک store مشترک (مثل
Redis) جایگزین بشه — نکته‌اش توی خود فایل هم هست.

### اعتبارسنجی ورودی‌ها
`lib/validate.ts` — فرمت ایمیل، فرمت شماره موبایل ایران، فرمت یوزرنیم
(فقط حروف انگلیسی/عدد/آندرلاین)، سیاست رمز عبور (حداقل ۸ کاراکتر + حداقل
یک حرف و یک عدد)، و محدودکردن طول رشته‌های آزاد کاربر (اسم، یادداشت،
موضوع رودمپ و…). این‌ها روی مسیرهای ثبت‌نام، ترید، کالری، ورزش، و
رودمپ‌ساز اعمال شدن.

### پیام خطای عمومی در ثبت‌نام
قبلاً اگه شماره یا یوزرنیم تکراری بود، پیام دقیق می‌گفت کدوم؛ الان پیام
عمداً کلیه («امکان ثبت‌نام با این اطلاعات وجود ندارد») تا نشه با امتحان
شماره‌های مختلف فهمید کدوم شماره قبلاً ثبت‌نام کرده (User Enumeration).

### هدرهای امنیتی HTTP
`next.config.js` حالا روی هر پاسخ این‌ها رو می‌فرسته:
`X-Frame-Options: DENY` (جلوگیری از clickjacking)،
`Content-Security-Policy`، `Strict-Transport-Security` (HSTS)،
`X-Content-Type-Options: nosniff`، `Referrer-Policy`، `Permissions-Policy`،
و حذف هدر `X-Powered-By` (که استک فنی رو لو می‌داد).

### چیزهایی که از قبل امن بودن (و همچنان هستن)
- همه کوئری‌ها با Prisma پارامتری‌شدن — بدون هیچ raw SQL، پس در برابر
  SQL Injection ایمنیم.
- هیچ‌جا `dangerouslySetInnerHTML` یا `eval` استفاده نشده — React خودش
  محتوای متنی رو escape می‌کنه، پس در برابر XSS ذخیره‌شده ایمنیم.
- همه روت‌های حذف/ویرایش با `where:{id, userId}` کوئری می‌زنن، نه فقط
  `{id}` — یعنی کاربر A نمی‌تونه داده کاربر B رو با حدس‌زدن ID دستکاری کنه (IDOR).
- رمزهای عبور با bcrypt (۱۲ round) هش می‌شن، هیچ‌جا متن‌خام ذخیره نمی‌شه.
- session با JWT امضاشده (NEXTAUTH_SECRET) کار می‌کنه؛ `isSuperAdmin` از
  سمت کلاینت قابل جعل نیست چون از دیتابیس میاد و توی JWT امضاشده قرار می‌گیره.

## هنوز مونده (برای قبل از لانچ واقعی)
- **حتماً رمز حساب سوپریوزر پیش‌فرض (`mohammadreza`) رو عوض کن** قبل از production
- Rate limiting با Redis (نه در-حافظه) اگه چند سرور شدید
- CSP سخت‌گیرانه‌تر با nonce به‌جای `'unsafe-inline'` روی script-src
- 2FA برای حساب ادمین
- لاگ‌گیری و مانیتورینگ تلاش‌های ورود مشکوک
- تست نفوذ (Penetration Testing) قبل از لانچ عمومی
- بک‌آپ خودکار دیتابیس
